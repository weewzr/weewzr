## The problem

A TRISO fuel particle is a small kernel wrapped in coating layers. STRATO asks how fast fission products such as silver, caesium and strontium diffuse out through those layers, and it tracks the release fraction, the share of the initial inventory that has left through the outer surface. The aim is a model in which every equation, numerical method and parameter can be traced to a derivation or a published source.

Version 1.0 is Phase 1 of that plan. It provides the verified numerical foundation, and physical inputs from the literature are added in later versions. Its bundled example uses synthetic parameters chosen for verification. They are not measured TRISO properties. The model holds temperature constant, gives each layer a constant diffusivity and places the whole initial inventory in the kernel. Radioactive decay, fission-product generation and temperature-dependent diffusivity are excluded and belong to the v2.0 scope.

## Approach

The particle has five concentric spherical layers: kernel, buffer, inner pyrolytic carbon, silicon carbide and outer pyrolytic carbon. Each obeys spherical diffusion with its own diffusivity. The centre is a symmetry point, interfaces are in perfect contact so that concentration and flux are continuous, and the outer surface absorbs everything that arrives.

The same problem is solved twice. Code C is an exact multilayer Sturm-Liouville eigenfunction series, with eigenvalues isolated by a Sturm count and refined by bisection, and it reports its mode count, the time from which the series is valid and its round-off floor. Code B is a conservative finite-volume scheme with exact shell volumes and wall areas, series-resistance interface conductances and Backward Euler stepping. Each step is one tridiagonal solve by subtraction-free elimination, and inventory, cumulative release and their balance are tracked throughout. Two written documents derive both methods, and the second links each final equation to its pseudocode and to the Rust code with file and line references.

## Verification

The two methods check each other, and a regression test compares the build with the delivered v1.0 outputs. The verification example asserts every claim it prints. The CI workflow checks formatting, lints with warnings denied, runs the tests and the documentation build, runs the verification example and audits dependencies. The Final Deliverable records 20 Rust tests, all passing in its acceptance check, and marks each numerical property with an evidence status that runs from proved down to claimed only. It also lists 44 known inconsistencies between the earlier documents, code comments, tests and code, items I1 to I26 and K1 to K18, with a recommended correction for each.

These checks show that the code solves its equations correctly. They say nothing about whether the equations or the inputs match real particles, because two methods can agree and still rest on the same wrong physics. Comparison with measured AGR-1 release data is planned for v2.0.

The printed temporal orders fall below one because the spatial error of the 200-cell mesh enters the comparison. The gap of 1.27e-4 between the single run and the exact series is mostly time-step error, since Backward Euler is first order, and the verification output (tests/golden/v1.0/verify_stdout.txt) puts the spatial error at 200 cells at 5.5e-6.

## What it does not cover

- The inputs are synthetic, and no literature parameters are bundled yet.
- Temperature is constant and diffusivity does not depend on it. The input temperature is recorded only.
- There is no radioactive decay and no fission-product generation, so all inventory starts in the kernel.
- Interfaces are in perfect contact with no partition coefficients, and the outer surface is a perfect sink.
- The model covers a single intact particle. Matrix transport, failed particles and particle populations are not modelled.
- Backward Euler is first order in time, so the time step controls accuracy at early times.

## Technology

STRATO is a Rust program built with Cargo, reading TOML input and writing CSV and SVG output. Python scripts under `scripts/` check the derivations and draw the figures. GitHub Actions runs the CI workflow and a documentation workflow, and the PDF documents are built with pandoc and XeLaTeX. The project is MIT licensed.
